# work03 — 데이터 업데이트 + 2학기 자료 추가 + 어드민 페이지

> 이 문서는 **데이터 업데이트 또는 어드민 페이지 작업(work03)을 시작할 때만** 참조합니다.

## 상태

미착수. 데이터 도착 시점(11월 말~12월 초)에 맞춰 착수.

## 이 작업의 두 갈래

### A. 데이터 업데이트 (트리거성 단발 작업)

- **1학기 콘텐츠 기반 데이터**를 Supabase에 채워 넣는 작업. 데이터가 도착하면 몇 시간~하루 안에 끝나는 수준
- **데이터 도착 조건**: SUMMIT 밴드 임원진(부회장 본인 포함)의 선행 작업이 먼저 끝나야 데이터가 나옴 — 이 선행 작업 자체는 동아리 업무이지 개발 작업이 아님
- **외부 데드라인**: 12월 정기공연 전까지 반영 완료
- 지금(여유 있을 때) 미리 할 수 있는 것: 데이터 스키마/폼 구조는 데이터 도착 전에 미리 설계 가능 (기존 `Line Up`, `Setlist` 테이블 구조 참고)

### B. 어드민 페이지 (work02 백엔드 위에 구축하는 신규 기능)

- 목적: 동아리 콘텐츠(공연 정보, 셋리스트, 팀 정보 등)를 DB에서 직접 다룰 수 있는 관리자 웹페이지
- **스코프는 최소로 유지**: 로그인 + 텍스트/이미지 CRUD. 그 이상(권한 세분화, 승인 워크플로우 등)은 지금 단계에서 설계하지 않음
- 인증은 work02에서 본인이 직접 구현한 로직을 그대로 사용
- 12월 정기공연 시기에 착수해 **2027년까지 기능 확장** (새 팀원 합류 전제 — 팀원이 데이터를 직접 관리할 수 있는 도구가 되는 것이 장기 목표)

## 우선순위 충돌 시 판단

- 데이터 업데이트(A)는 외부 데드라인(공연 날짜)이 있고, 어드민 페이지(B)와 백엔드 Phase 2(work02)는 자체 목표(데드라인 없음)
- **데이터가 도착하면 A를 먼저 처리**하고, B와 work02 Phase 2는 그 사이사이 여유 시간에 진행
- A는 어드민 페이지 완성을 기다리지 않음 — 어드민이 없어도 Supabase 콘솔이나 스크립트로 직접 데이터를 넣을 수 있으면 그렇게 처리. 어드민은 "다음 학기부터 더 쉽게 하기 위한" 도구이지, 이번 데이터 반영의 전제조건이 아님

## 2027년 확장 고려사항 (지금 결정하지 않아도 되는 것)

- 어드민 페이지 권한 체계 (팀원별 접근 범위)
- 콘텐츠 승인/버전 관리 플로우
- 위 항목들은 실제 팀원이 합류하고 니즈가 구체화된 시점에 재검토 — 지금 미리 설계해서 과설계하지 않음
