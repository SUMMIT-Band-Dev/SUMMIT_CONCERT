# SUMMIT 관리자 페이지 MVP PRD

## 🎯 핵심 정보

**목적**: SUMMIT 밴드 임원진이 팀/곡/유튜브 연결 정보를 코드 개입 없이 직접 갱신할 수 있게 한다
**사용자**: SUMMIT 밴드 임원진(비개발자 콘텐츠 관리 담당자)

## 🚶 사용자 여정

```
1. 로그인 페이지
   ↓ 아이디/비밀번호 입력 → 로그인 버튼

   [인증 성공] → 팀 관리 페이지
   [인증 실패] → 로그인 페이지 유지 + 에러 표시
   ↓

2. 팀 관리 페이지
   ↓ 팀 카드 선택

3. 곡 관리 페이지 (선택한 팀의 곡 패널)
   ↓ 곡 등록/수정 완료

4. [완료] → 팀 관리 페이지로 복귀 또는 유튜브 연결 관리 페이지로 이동(상단 메뉴)
```

- 미로그인 상태로 관리자 페이지(팀 관리/곡 관리/유튜브 연결 관리) 접근 시 로그인 페이지로 자동 리디렉션
- 유튜브 연결 관리 페이지는 상단 메뉴를 통해 언제든 독립적으로 진입 가능

## ⚡ 기능 명세

### 1. MVP 핵심 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F003** | 팀 목록 조회 | 전체 팀을 공연 순서대로 조회 | 팀 관리의 기준 화면 | 팀 관리 페이지 |
| **F004** | 팀 등록 | 팀명+공연일자(day)+공연순서(performanceOrder)를 한 세트로 업로드 | 신규 팀 데이터 입력의 핵심 기능 | 팀 관리 페이지 |
| **F005** | 팀 정보 수정 | 팀명, 공연일자 개별 수정 | 팀명 변경 시 FK 관계를 깨지 않고 갱신 | 팀 관리 페이지 |
| **F006** | 공연 순서 재정렬 | 드래그 등으로 순서 변경 후 전체 순서 일괄 업데이트 | 공연 순서는 매 학기 바뀌는 핵심 데이터 | 팀 관리 페이지 |
| **F008** | 팀별 곡 조회 | 팀 선택 시 해당 팀 소속 곡만 필터링해서 조회(패널 UI) | 곡 관리의 기준 화면 | 곡 관리 페이지 |
| **F009** | 곡 등록/수정 | 곡 제목, 가수 입력·수정 | 셋리스트 데이터 입력의 핵심 기능 | 곡 관리 페이지 |
| **F011** | 유튜브 배치 추천 검색 | `youtube_url`이 NULL인 곡들을 일괄 검색·스코어링 (YouTube Data API 일일 quota 100회 제한 고려, 이미 검토 완료된 곡은 재검색 대상에서 제외) | 곡마다 수동 검색하는 반복 작업 제거 | 유튜브 연결 관리 페이지 |
| **F012** | 유튜브 추천 리뷰 | 추천 영상(제목+채널명+썸네일)을 목록으로 보여주고 승인/반려 (반려 시 해당 곡은 이후 배치 재검색 대상에서 제외) | 자동 매칭 결과를 사람이 검증하는 필수 단계 | 유튜브 연결 관리 페이지 |

### 2. MVP 필수 지원 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F001** | 관리자 로그인 | JWT 기반 관리자 인증. 기존 방문자용 서비스 로그인과 무관 | 관리자 기능 접근을 위한 최소 인증 | 로그인 페이지 |

| **F013** | 유튜브 URL 수동 수정 | 추천이 틀렸을 경우 직접 URL 입력해 교정 | 자동 매칭 실패 케이스에 대한 최종 보정 수단 | 유튜브 연결 관리 페이지 |

## 🗄️ 데이터 모델

### AdminUser (관리자 계정)
| 필드 | 설명 | 타입/관계 |
|------|------|----------|
| id | 고유 식별자 | int8 |
| username | 로그인 아이디 | string |
| passwordHash | 비밀번호 해시 | string |

### LineUp (팀)
> 실제 Supabase 테이블은 `Line Up`. 아래 필드명은 개념 설명용이며, Prisma `db pull` 시 실제 DB 컬럼명(괄호 안)을 그대로 따른다.

| 필드 | DB 컬럼명 | 설명 | 타입/관계 |
|------|----------|------|----------|
| id | id | 고유 식별자 | int8 |
| teamName | team_name | 팀명 | string |
| day | day | 공연일자 | string |
| performanceOrder | performanceOrder | 공연 순서 | number |
| cardImageUrl | image_src | 카드뉴스 이미지 URL | string |

### Setlist (곡)
> 실제 Supabase 테이블은 `Setlist`. 아래 필드명은 개념 설명용이며, Prisma `db pull` 시 실제 DB 컬럼명(괄호 안)을 그대로 따른다.

| 필드 | DB 컬럼명 | 설명 | 타입/관계 |
|------|----------|------|----------|
| id | id | 고유 식별자 | int8 |
| teamId | teamId | 소속 팀 | → LineUp.id |
| title | title | 곡 제목 | string |
| singer | singer | 가수 | string |
| albumCoverUrl | album | 앨범 커버 URL | string |
| youtubeUrl | youtube_url | 유튜브 링크 | string |
| youtubeReviewStatus | (신규 컬럼 추가 필요) | 유튜브 추천 검토 상태 (pending/approved/rejected) | enum 또는 string |

### 🔗 외부 연동

- **iTunes Search API** — 앨범 커버 자동 매칭
  - 분당 약 20회 rate limit 존재. 개별 곡 입력 단위로는 문제없으나, 대량 마이그레이션 시나리오(work03)에서는 별도 고려 필요
- **기존 유튜브 스코어링 로직** (`src/app/api/youtube/`) — 배치 추천 검색에 재사용
  - YouTube Data API `search.list`는 별도 quota 버킷 적용, 일일 기본 한도 100회 → 하루 최대 약 100회 검색 가능
  - 배치용 API 키와 기존 실시간 폴백(`src/app/api/youtube/top-video`)용 API 키를 분리 사용 (관리자 배치 작업이 일반 방문자 폴백의 quota를 잠식하지 않도록)
- **Supabase Storage** — 카드뉴스 이미지 업로드
